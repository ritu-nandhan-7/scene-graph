# Phase E2 — Browser Preprocessing Parity Measurement

**Date:** October 21, 2026
**Classification:** **COMPLETED — PARITY NOT ACHIEVED; DO NOT INTEGRATE**
**Scope:** Isolated files under `experiments/browser-feasibility/`. Production
pipeline code, frontend integration, checkpoints, and source ONNX assets were
not modified.

## What E2 measured

E2 replaced E1's Canvas tensor-resize operations with explicit browser CPU
kernels and compared five fixed Visual Genome fixtures in Chrome against saved
Python references:

1. decoded Pillow RGB pixels;
2. static `640 x 640` YOLO input tensors, using Python/OpenCV `INTER_LINEAR`
   letterboxing and browser half-pixel linear resizing;
3. raw output of the same immutable static YOLO ONNX graph;
4. static-route post-NMS detections; and
5. browser CLIP crop input tensors against unchanged-production E1
   Pillow/OpenCLIP reference tensors.

The Python detector reference uses Python ONNX Runtime against the exact
browser static ONNX artifact. It deliberately does not construct YOLO-World or
OpenCLIP, avoiding their external cache/network initialization paths. The
production rectangular scene, pair order, crop records, and Pillow/OpenCLIP
tensors are unchanged references generated by E1's production
`SceneGraphPipeline` run.

## Chrome execution

Chrome `155.0.8059.85` completed six actual page runs:

- five fixtures in WebGPU-preferred page mode; and
- `fixture-1` in WASM fallback mode.

The detector itself intentionally uses its existing WASM session in both modes;
the provider selector remains relevant to the broader E1 model-chain setup.
All browser ONNX inference occurred in page JavaScript. Playwright/Node only
served the page and drove it.

`pageErrors` was empty. Chrome console output contained only a missing-resource
404 and ONNX Runtime's non-fatal unknown-CPU-vendor warning.

### Detector preprocessing

The explicit browser linear path is a substantial improvement over Canvas as a
controlled preprocessing implementation:

- `many-107900` is exactly equal for all `1,228,800` YOLO input elements.
- For the other four images, 91.29%–91.88% of elements are exactly equal.
- Every remaining YOLO input discrepancy is at most `0.0039215982`, exactly
  one 8-bit channel level after `/255` normalization; no input element differs
  by more than that.

This is **not** sufficient for tensor parity. The remaining resize rounding
behavior is still distinguishable on four fixtures.

### Detector inference and detections

Raw outputs are not equivalent even when the input is exactly equal:

- raw-output MAE is `4.188586`–`4.203466` across all fixtures;
- raw-output maximum absolute error is `631.860413`–`634.080383`.

The strict detection comparison consequently reports every row changed because
the Python decoder rounds boxes to integer pixels while the browser decoder
keeps subpixel boxes and confidences. Semantically, labels align for four
WebGPU-preferred fixtures; `moderate-107899` has two label mismatches, and
`fixture-1` has a count change (Python 11 vs browser 10). Therefore static
detection parity is not established.

### CLIP crop preprocessing

The explicit browser bicubic/antialias approximation is also not equivalent to
the production Pillow/OpenCLIP transform. Across the five fixture pair batches,
CLIP input MAE ranges from `0.029148` to `0.123045`, with maximum absolute
error from `1.500777` to `2.776437`. Exact element fractions range only from
4.39% to 27.35%.

E2 therefore does not claim CLIP-feature, relationship-logit, or final
scene-graph parity. Those downstream results are sensitive to the measured
input differences, as E1 already demonstrated.

## Important route boundary

The browser detector artifact is immutable and accepts only static `640 x 640`
inputs. Production `YoloWorldDetector.detect()` invokes normal Ultralytics
prediction defaults, which can take the rectangular-letterbox route. E2 reports
static ONNX parity separately and does not misrepresent it as identical to the
production detector route.

## Recommendation

Do not modify the production frontend or enable a browser scene-graph mode on
the basis of E2. Before integration, resolve both of these acceptance failures:

1. reproduce OpenCV resize/rounding byte-for-byte in browser code (or make the
   server-side preprocessing artifact available); and
2. establish why the same static YOLO ONNX graph has materially different raw
   outputs between Python ONNX Runtime CPU and browser ONNX Runtime WASM, then
   validate decoded detections under a single canonical postprocessing contract.

After detector parity, replace the CLIP approximation with an implementation
verified directly against Pillow/OpenCLIP's bicubic antialias behavior, and then
re-measure CLIP features, relationship logits/probabilities, and final graph
edges on the same fixtures.
